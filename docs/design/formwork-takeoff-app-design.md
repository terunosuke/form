# 型枠材料拾い出しアプリ 設計書(初期バージョン)

本書は、要求仕様(全27章)に基づき、指定された回答手順(第27章)の順序で設計をまとめたものである。

> **本アプリの注意書き(結果画面に常時表示)**
> 本アプリは入力された配置条件に基づいて型枠材料の数量を算出するものであり、型枠の構造安全性を判定するものではありません。各材料の規格および配置ピッチは、施工計画および構造検討に基づいて入力してください。

---

## 1. 現在確定している要件の整理

### 1.1 基本方針(確定)

* 構造計算・安全性判定は行わない。側圧からのピッチ自動設計は行わない。
* ベニヤ・桟木・鋼管・セパレーター・フォームタイ・Pコンの規格、向き、ピッチ、基準位置、端部位置は**すべて入力者が指定**する。
* アプリは指定された配置条件に従って材料を配置し、数量を算出するのみ。
* 情報不足時は数量計算を実行せず、不足項目を具体的に表示する(推測補完の禁止)。
* 結果画面に免責注意書きを表示する。

### 1.2 材料構成(確定)

コンクリート側から:①ベニヤ → ②桟木(根太材、ベニヤに直接当てる)→ ③鋼管(大引き材、桟木の外側)→ ④フォームタイ(鋼管を締め付け)→ ⑤セパレーター(対向型枠間の寸法保持)→ ⑥Pコン(セパ端部)。
3D画面で材料別(躯体含む7区分)の表示オン・オフを可能とする。

### 1.3 対象構造物(確定)

壁、擁壁、柱、梁、スラブ、フーチング。

* 壁・擁壁:鉛直面。片面/両面選択。型枠面をユーザー指定。
* 柱:平面ポリラインから生成。四角形は四辺を型枠面。多角形対応可能なデータ構造。
* 梁:梁側左/梁側右/梁底/梁端部を別管理。梁上面は標準で型枠なし。**梁底は梁側と別オブジェクト**。
* スラブ:スラブ底/端部/開口側面を別管理。初期版は底+外周端部が主対象。
* フーチング:各側面の型枠有無を選択。底面は標準なし、手動で有効化可能。

### 1.4 入力方法(確定)

画像・PDF・カメラ撮影・手描きスケッチの読み込み、直接ポリライン作図、簡易図形ツール。画像解析結果は**必ずユーザー修正後に確定**。複雑な施工図の完全自動認識は目標外。

### 1.5 縮尺(確定)

寸法線選択/二点間距離/既知部材寸法のいずれかで設定。**縮尺未設定では拾い出し実行不可**。

### 1.6 ポリライン(確定)

外郭ポリラインは「型枠設置面の輪郭または通り」を表す(躯体外周ではない)。頂点追加・削除・移動、辺移動、辺長数値入力、水平/垂直/平行/直角拘束、分割・結合、開閉切替、Undo/Redo。四角形は入力形状をそのまま使用。

### 1.7 重なり(確定)

同一平面位置に複数部材(柱・壁・梁・スラブ・フーチング)を重ねて登録可能。同一ポリラインを複数部材から参照。高さ・厚さ・型枠面・材料配置・施工区分・脱型区分は部材ごとに独立。統合禁止。

### 1.8 高さ(確定)

全体基準高さ→頂点・辺ごとの変更。一括変更、コピー、上端勾配、3Dドラッグ、右クリック数値入力、各種ビュー。**初期版は型枠下端水平のみ**。

### 1.9 勝ち負け(確定)

標準立て込み順序:柱→壁→梁→スラブ。標準優先順位:柱先行、壁は柱に突き付け、梁側は柱・壁と取り合い考慮、梁底は独立、スラブ底は梁と取り合い考慮。接合部ごとに通し/止め/控除面/計上先をユーザー変更可能。

### 1.10 脱型区分(確定)

標準グループ:柱/壁/梁側/スラブ端部/スラブ底/梁底。梁底は別集計で最後まで残置可能。集計区分:先行脱型可能/支保工関連/スラブ底/梁底/最後まで残置。

### 1.11 材料設定(確定)

* ベニヤ:標準910×1,820mm、縦使い標準。**面積割り算ではなく実際の矩形割付**で算出。端材転用なし(端材一覧・廃棄見込み面積は表示)。
* 桟木:縦桟木(鉛直配置)標準。水平ピッチ、端部距離、端部/継ぎ目/隅部の追加配置。
* 鋼管:角パイプ・水平・一段1本が標準。丸パイプ・二本抱き・複数列に拡張可能な構造。
* セパレーター:標準W3/8。**長さは材料マスタから決定、マスタ未登録時はユーザー直接入力(推測禁止)**。
* フォームタイ:両面型枠でセパ両端配置が標準。使用個数はマスタで変更可能。
* Pコン:セパ配置本数×片側/両側条件から算出。セパ長さへの加算/控除寸法を保持。

### 1.12 配置ピッチ(確定)

等間隔配置(指定ピッチ固定+端部余り/均等割り)、二段階配置(境界高さで上下範囲別ピッチ)。セパは水平・鉛直別設定、範囲別に水平ピッチ変更可。桟木の高さ範囲別ピッチは分割材扱い(連続/別材を設定)。

### 1.13 計算過程の追跡(確定)

すべての数量について、入力値・規格・ピッチ・開始/終了位置・本数・計算式・端数処理・重複控除・手動補正・最終数量を確認可能とする。

### 1.14 データ保存(確定)

元画像・縮尺・ポリライン・部材・高さ・厚さ・型枠面・勝ち負け・脱型区分・材料マスタ・ピッチ・配置結果・手動修正・集計結果を保存。材料条件変更時は形状を維持したまま再計算。

### 優先質問(数量計算への影響が大きいもののみ、5件)

#### 質問1(U-1):セパレーター長さマスタの初期データ

* **質問の目的**:セパレーター長さは「壁厚+Pコン・端部形状・仕上げ条件による加減」で決まり、マスタ未登録なら計算不能(仕様どおり手入力要求)となるため、初期マスタの出所を確定したい。
* **選択肢**:
  A. 貴社で使用中のメーカーカタログ(例:岡部、東海建商など)の規格表を提供いただき、それを初期マスタとして登録する。
  B. 初期マスタは空とし、プロジェクトごとにユーザーが「壁厚→セパ長さ」対応表を入力する。
  C. 一般的な「セパ長さ=壁厚(C型・両面Pコン時)」等の代表式のみ登録し、それ以外は手入力。
* **各選択肢の影響**:Aは初回から自動決定可。Bは初回入力の手間が大きいが誤りが混入しない。Cは該当条件以外で毎回手入力になる。いずれもマスタ未登録条件では長さを推測せず手入力を要求する動作は共通。
* **推奨する初期設定**:B(空マスタ+手入力)で実装し、A のカタログ値を受領次第マスタ投入。
* **後から変更可能か**:可能。マスタは追加・編集式で、変更後に再計算できる。

#### 質問2(U-2):柱型枠の締固め方式の標準

* **質問の目的**:柱にセパレーター・フォームタイを配置するか、コラムクランプ等の別金物とするかで、セパ・フォームタイ・Pコンの数量が大きく変わる。
* **選択肢**:
  A. 柱もセパ+フォームタイ方式を標準とし、対面同士でセパを配置する。
  B. 柱はコラムクランプ方式を標準とし、初期版ではクランプは「段数×周長」で参考数量のみ算出。
  C. 柱ごとにユーザーが方式を選択(既定はセパ方式)。
* **各選択肢の影響**:Aはセパ類の数量が柱分増える。Bはセパ類が柱で0になり、別品目が増える。Cは入力項目が1つ増えるが実態に合う。
* **推奨する初期設定**:C(柱ごと選択、既定はセパ方式)。
* **後から変更可能か**:可能。部材単位の設定であり、切替後に再計算できる。

#### 質問3(U-3):ベニヤ割付原点の標準

* **質問の目的**:同じ面積でも割付原点(左下基準か中央基準か)で全判枚数と切断材枚数が変わる。
* **選択肢**:
  A. 各型枠面の左下角を原点とし、右・上方向へ割り付ける(切断材は右端・上端に発生)。
  B. 面の中央から左右対称に割り付ける(切断材が両端に発生)。
  C. 面ごとにユーザーが原点(左下/右下/中央)を選択(既定は左下)。
* **各選択肢の影響**:Aは切断枚数が最少になりやすい。Bは対称で見栄えが良いが切断枚数が増えやすい。Cは柔軟だが操作が1つ増える。
* **推奨する初期設定**:C(既定は左下)。
* **後から変更可能か**:可能。面単位の設定で、変更後に板割りを再計算できる。

#### 質問4(U-4):数量の丸め・予備率の標準

* **質問の目的**:最終出力(発注用数量)の丸め単位と予備率の既定値がないと、集計値が確定しない。
* **選択肢**:
  A. 丸めなし(計算値そのまま、小数含む)を既定とし、丸めは材料ごとに任意設定。
  B. 材料ごとに「切り上げ(1枚/1本/1個単位)」を既定とし、予備率0%。
  C. Bに加えて材料別予備率(例:ベニヤ5%)を既定投入。
* **各選択肢の影響**:Aは拾い量の生値が見えるが発注にそのまま使えない。Bは発注向きで安全側。Cは会社ごとの実務値に依存し、根拠のない既定値は本アプリの方針(推測禁止)に反するおそれ。
* **推奨する初期設定**:B(1単位切り上げ、予備率0%。予備率は明示入力時のみ加算し、計算書に予備率行を表示)。
* **後から変更可能か**:可能。丸め・予備率は集計時パラメータで、再計算のみで反映。

#### 質問5(U-5):梁底型枠幅の算出基準

* **質問の目的**:梁底ベニヤの幅を「梁幅」とするか「梁幅−側枠ベニヤ厚×2」等とするかで梁底の板割りが変わる(側枠が梁底に乗るか、梁底が側枠間に落ち込むかの納まり)。
* **選択肢**:
  A. 梁底幅=梁幅(側枠は梁底の外側に立つ:底勝ち)。
  B. 梁底幅=梁幅−(側枠ベニヤ厚+桟木せい)×2 等の控除式(側勝ち)。
  C. 取り合い設定(第10章の勝ち負け)の一部として梁ごとに選択(既定は底勝ち)。
* **各選択肢の影響**:板取り寸法が数十mm変わり、切断材の枚数・寸法に影響。
* **推奨する初期設定**:C(既定は底勝ちA)。
* **後から変更可能か**:可能。勝ち負け設定と同じ枠組みで変更→再計算。

## 3. 初期バージョンの機能範囲

1. **プロジェクト管理**:作成・保存・再編集(第26章の全保存対象)。
2. **材料マスタと材料条件設定**:ベニヤ/桟木/鋼管/セパ/フォームタイ/Pコン(第13〜18章の全設定項目)、等間隔・二段階ピッチ(第19章)。
3. **形状入力**:画像・PDF・撮影・スケッチ読込、直接作図、簡易図形ツール。簡単な平面スケッチのみ対象。認識結果は下書き扱い(ユーザー確定必須)。
4. **縮尺設定**:3方式。未設定時は拾い出しロック。
5. **ポリライン編集**:第6章の全編集操作(拘束4種、Undo/Redo含む)。
6. **構造部材定義**:壁・擁壁・柱・梁・スラブ・フーチング。同一ポリラインの複数部材参照。部材別寸法入力(第9章)。
7. **高さ設定**:第8章の操作一式。型枠下端は水平のみ。
8. **型枠面生成**:部材→型枠面オブジェクト生成(第20章の属性一式)。
9. **勝ち負け・重複控除**:自動候補検出+取り合い一覧+3D/2D色分け+ユーザー上書き(第10・21章)。
10. **材料割付**:ベニヤ実割付、桟木、鋼管、セパ、フォームタイ、Pコン(第13〜18章の数量内訳)。
11. **3D確認**:材料別表示切替、配置・干渉・重複確認、手動修正。
12. **数量集計**:部材別/型枠面別/材料別/規格別/長さ別/脱型区分別。計算根拠トレース(第25章)。
13. **出力**:Excel・CSV・PDF、材料一覧、板割図、配置図、3D画像、計算条件一覧。
14. **免責注意書きの常時表示**、不足情報の明示(計算ブロック)。

## 4. 将来対応とする機能

第22章のとおり:側圧計算/構造安全性判定/自動ピッチ設計/許容荷重判定/ベニヤ・桟木・鋼管・セパの各種構造計算/開口部自動認識/複雑な入隅・出隅自動処理/内側空洞自動処理/地盤なり・段差のある型枠下端/端材転用/二次元ネスティング/複雑な施工図の完全自動認識。

追加で将来枠に置くもの:多角形柱の自動面生成の高度化(データ構造は初期版から対応)、スラブ開口の自動処理、支保工数量(U-13の回答次第)、クラウド同期・共同編集(U-7/U-14次第)。

**拡張性の担保方法**:型枠面に `deductionRegions`(控除領域)と `bottomProfile`(下端形状。初期版は `{type:"horizontal", z}` のみ)を最初から持たせる。ピッチ定義は `PitchRule` の判別可能ユニオン(discriminated union)とし、新方式(地盤なり等)を型追加のみで拡張できるようにする。材料配置結果は材料種別ごとのレコード配列で持ち、ネスティング導入時も placement レコードの生成器差し替えで対応する。

## 5. 構造部材と型枠面のデータモデル

内部単位はすべて **mm**、座標は右手系(X:東、Y:北、Z:上)、平面図はXY平面とする。スキーマはTypeScript風の擬似定義で示す(実装言語を拘束しない)。

```ts
// ---- 幾何(共有ジオメトリ) ----
interface Point2D { x: number; y: number }

interface Polyline {
  id: PolylineId;
  points: Point2D[];          // 順序付き頂点列
  closed: boolean;            // 開/閉
  constraints: Constraint[];  // 水平・垂直・平行・直角
  sourceType: "drawn" | "image_traced" | "shape_tool";
  sourceImageId?: ImageId;    // トレース元
  confirmed: boolean;         // 画像解析結果はfalseで生成、ユーザー確定でtrue
}

type Constraint =
  | { type: "horizontal"; edgeIndex: number }
  | { type: "vertical";   edgeIndex: number }
  | { type: "parallel";   edgeA: number; edgeB: number }
  | { type: "perpendicular"; edgeA: number; edgeB: number };

// ---- 構造部材 ----
type MemberKind = "column" | "wall" | "retaining_wall" | "beam" | "slab" | "footing";

interface StructuralMemberBase {
  id: MemberId;
  kind: MemberKind;
  name: string;                    // 例 "C1", "W3", "G2"
  polylineRefs: PolylineRef[];     // 同一ポリラインを複数部材が参照できる(第7章)
  baseLevel: number;               // 下端高さ Z
  topLevel: number;                // 上端高さ Z
  constructionGroup: string;       // 施工区分(打設区分)
  strippingGroupOverride?: StrippingGroupId; // 脱型区分の個別上書き
  vertexLevelOverrides?: VertexLevel[];      // 頂点別上端/下端(第8章)
  topSlope?: { edgeIndex: number; slope: number }[]; // 上端勾配
}

interface PolylineRef {
  polylineId: PolylineId;
  role: "outline" | "axis";   // 輪郭として使うか、通り(芯線)として使うか
  offset?: number;             // 通り参照時の芯からの振り分け
}

interface WallMember extends StructuralMemberBase {
  kind: "wall" | "retaining_wall";
  thickness: number;
  formworkSides: "both" | "sideA" | "sideB";  // 片面/両面と対象面
  formStartLevel?: number;    // 型枠開始高さ(省略時 baseLevel)
  formEndLevel?: number;      // 型枠終了高さ(省略時 topLevel)
}

interface ColumnMember extends StructuralMemberBase {
  kind: "column";
  // 断面はポリライン(四角形〜多角形)。四角形なら幅・奥行きを別途表示。
  tieMethod: "separator" | "column_clamp";     // 質問2(U-2)
  faceFormworkFlags: boolean[];                 // 辺ごとの型枠有無(既定すべてtrue)
}

interface BeamMember extends StructuralMemberBase {
  kind: "beam";
  width: number;               // 梁幅
  depth: number;               // 梁せい
  // 位置は polylineRefs(axis) + width の振り分け、または outline 参照
  sideFormLeft: boolean;       // 梁側左の有無
  sideFormRight: boolean;      // 梁側右の有無
  bottomForm: boolean;         // 梁底の有無
  endForms: { start: boolean; end: boolean };  // 梁端部
  // 梁上面は型枠面を生成しない(標準)
}

interface SlabMember extends StructuralMemberBase {
  kind: "slab";
  thickness: number;
  bottomForm: boolean;         // スラブ底
  edgeFormFlags: boolean[];    // 外周辺ごとの端部型枠有無
  openings: Opening[];         // データ構造のみ用意(自動処理は将来)
}

  kind: "footing";
  sideFormFlags: boolean[];    // 各側面の有無
  bottomForm: boolean;         // 既定 false、手動で true 可
}

// ---- 型枠面(第20章) ----
type FaceType =
  | "wall_side" | "column_side"
  | "beam_side_left" | "beam_side_right" | "beam_bottom" | "beam_end"
  | "slab_bottom" | "slab_edge" | "slab_opening_side"
  | "footing_side" | "footing_bottom";

interface FormworkFace {
  id: FaceId;
  memberId: MemberId;
  memberKind: MemberKind;
  faceType: FaceType;
  // 面ローカル座標系:原点=面の左下、U=幅方向、V=高さ方向、法線=コンクリートから外向き
  origin3D: Point3D; uAxis: Vec3; vAxis: Vec3;
  outline: Point2D[];          // 面ローカルUV座標の外形(初期版は矩形が主)
  width: number; height: number; area: number;   // 控除前
  singleOrDouble: "single" | "double";
  pairFaceId?: FaceId;         // 両面型枠の対向面(セパはペア単位で算出)
  erectionOrder: number;       // 施工順序(柱1→壁2→梁3→スラブ4を既定)
  strippingGroup: StrippingGroupId;
  adjacentFaces: FaceAdjacency[];      // 隣接型枠面と取り合い種別
  junctionResolutions: JunctionId[];   // 勝ち負け設定への参照(第9節)
  deductionRegions: Region2D[];        // 控除領域(UV座標の矩形/多角形)
  netArea: number;                      // 控除後面積
  layoutOrigin: "bottom_left" | "bottom_right" | "center"; // 質問3(U-3)
  // 材料割付結果(第11〜15節の出力)
  plywoodLayout?: PlywoodLayoutResult;
  battenLayout?: BattenLayoutResult;      // 桟木
  pipeLayout?: PipeLayoutResult;          // 鋼管
  separatorLayout?: SeparatorLayoutResult;
  formTieResult?: FormTieResult;
  pconResult?: PconResult;
  calcBlockers: MissingInput[];        // 不足情報(あれば計算不可)
}
```

**要点**

* 幾何(Polyline)と部材(Member)を分離し、`polylineRefs` で N:1 参照にすることで「壁と梁が同じ通りを共有」(第7章)を実現する。
* 数量は必ず `FormworkFace` を経由して算出する(第20章「3D躯体から直接算出しない」)。
* `deductionRegions` と `netArea` により、勝ち負け・重複控除の結果が面単位で追跡できる。
* `calcBlockers` が空でない面は数量計算をスキップし、集計画面に不足項目を列挙する(第25章)。

## 7. 配置ピッチのデータモデル

桟木・鋼管・セパの3材料で共通の `PitchRule` を使う(第19章)。

```ts
type SpacingMode =
  | "fixed_pitch"      // 指定ピッチ固定、端部に余り
  | "equal_divide";    // 指定ピッチ以下で均等割り

interface UniformPitch {           // 等間隔配置
  type: "uniform";
  pitch: number;
  mode: SpacingMode;
  startOffset: number;             // 左端(下端)から最初の部材まで
  endOffset: number;               // 右端(上端)から最後の部材まで
  placeAtEnds: boolean;            // 端部への配置有無(桟木の型枠端部配置)
}

interface TwoStagePitch {          // 二段階配置(高さ方向)
  type: "two_stage";
  boundaryLevel: number;           // 境界高さ(型枠下端からの距離)
  lower: { pitch: number; mode: SpacingMode };
  upper: { pitch: number; mode: SpacingMode };
  placeAtBoundary: boolean;        // 境界位置に部材を置くか
  bottomOffset: number;            // 最下段の高さ
  topClearance: number;            // 最上段からの離れ
}

type PitchRule = UniformPitch | TwoStagePitch;   // 将来: GroundProfilePitch 等を追加

interface SeparatorPitchConfig {
  // 鉛直方向の範囲ごとに水平ピッチを変えられる(第19章の例に対応)
  verticalBands: {
    fromLevel: number; toLevel: number;
    horizontal: UniformPitch;      // 水平ピッチ
    verticalPitch: number;         // この帯内の鉛直ピッチ
  }[];
  edgeOffsets: { left: number; right: number; bottom: number; topClearance: number };
}

interface BattenPitchConfig {
  horizontal: PitchRule;           // 基本は水平方向ピッチ(縦桟木)
  heightBands?: {                  // 高さ範囲別ピッチ(任意)
    boundaryLevel: number;
    continuity: "continuous" | "separate";  // 上下の桟木が連続材か別材か
  };
  extraAtPanelJoints: boolean;     // ベニヤ継ぎ目への追加
  extraAtCorners: boolean;         // 出隅・入隅への追加
}
```

**配置計算の共通仕様**

* `fixed_pitch`:位置列 = `startOffset, startOffset+p, …`、`endOffset` を侵さない最後の点まで。余り寸法をレコード化して計算書に出す。
* `equal_divide`:有効長 `L' = L − startOffset − endOffset`、本数 `n = ceil(L'/p) `、実ピッチ `p' = L'/n ≤ p`。`p'` を計算書に出す。
* 二段階:境界で範囲を分割し各範囲に上記を適用。`placeAtBoundary=true` なら境界位置に1本置き、両範囲の起点を境界からとる。

## 8. 柱・壁・梁・スラブ・フーチングの重なり処理

1. **登録**:同一 `Polyline` を複数 `StructuralMember` が `polylineRefs` で参照する。ジオメトリは1つ、部材属性(高さ・厚さ・材料・施工/脱型区分)は部材ごとに独立保持(第7章)。統合処理は行わない。
2. **編集の伝播**:ポリラインを編集すると参照する全部材の形状が追従する。特定部材だけ形状を変えたい場合は「参照の複製(ポリラインをコピーして付け替え)」コマンドを用意する。伝播が起きる編集では、影響部材名を編集前に一覧表示する。
3. **空間の重なり検出**:部材の3D占有域(ポリライン×高さ範囲)同士の交差を検出し、「重なり一覧」に列挙する(壁×梁が同位置・高さ帯重複、など)。これは第21章の重複控除候補の入力になる。
4. **型枠面の帰属**:重なっていても型枠面は各部材から独立に生成する。二重拾いの解消は面をマージするのではなく、`deductionRegions` による控除と計上先指定で行う(次節)。

## 9. 型枠の勝ち負け処理

```ts
interface JunctionCandidate {           // 自動検出結果(第21章の一覧)
  id: JunctionId;
  kind: "column_wall" | "column_beam" | "wall_beam"
      | "beam_slab" | "beam_beam" | "wall_wall";
  faceA: FaceId; faceB: FaceId;
  overlapRegionA: Region2D;             // A面UV上の重複領域
  overlapRegionB: Region2D;
  autoResolution: JunctionResolution;   // 標準優先順位による自動判定
  userResolution?: JunctionResolution;  // ユーザー上書き(常に優先)
}

interface JunctionResolution {
  policy: "A_wins" | "B_wins" | "count_both" | "deduct_both"
        | "deduct_length" | "deduct_region";
  deductLength?: number;                // policy=deduct_length
  deductRegion?: Region2D;              // policy=deduct_region
  quantityOwner: "A" | "B";             // 重複部分をどちらの部材数量に計上するか
}
```

* **自動判定の標準**(第10章):優先度 柱(1)>壁(2)>梁側(3)>スラブ底(4)。優先度が高い側を「通し(勝ち)」、低い側の重複領域を `deductionRegions` に追加(負け側は「止め」)。梁底は独立管理のため自動判定の対象外とし、梁底×梁側の納まりは質問5(U-5)の設定で決める。
* **ユーザー変更**:取り合い一覧(表)と3D画面(接合部をクリック)から `userResolution` を設定。変更は当該面の控除領域と `netArea` の再計算だけをトリガーし、形状は変えない。
* **可視化**:自動控除領域=黄、ユーザー変更済み=青、両方計上(重複容認)=赤縞、で2D/3Dとも色分け(第21章)。
* **追跡性**:各面の計算書に「控除:接合部J-12(柱C1勝ち)により −0.35m²」の形で junction を明記する(第25章)。

## 10. 梁底型枠を独立管理する方法

* **別オブジェクト**:`FormworkFace.faceType = "beam_bottom"` を梁側(`beam_side_*`)と別の面として生成する。IDも割付結果も別。
* **別脱型区分**:既定 `strippingGroup = "beam_bottom"`。脱型区分マスタは {柱, 壁, 梁側, スラブ端部, スラブ底, 梁底} を既定シードとし、梁底は並び順最後(最後まで残置)とする。
* **別集計**:集計は必ず `strippingGroup` をキーに含めるため、梁側と梁底が同一規格ベニヤでも行が分かれる。「梁側+梁底の合算」列は作らない(第11章「まとめない」)。
* **支保工との関連**:梁底面に `supportRelated: true` フラグを持たせ、集計の「支保工と関連する材料」区分に紐づける(数量自体はU-13の回答まで対象外)。
* **幅の算出**:質問5(U-5)の設定(底勝ち/側勝ち)により梁底面の `width` を決定し、計算書に採用式を明記する。

## 11. ベニヤ割付アルゴリズム

入力:型枠面(UV外形、控除領域、`layoutOrigin`)、ベニヤ規格(幅・長さ・向き・切断代・目地方向)。

1. **向きの決定**:縦使い=長さ1,820を面のV(高さ)方向に、横使い=90度回転(第13章)。
2. **グリッド生成**:`layoutOrigin` を原点に、パネル寸法+切断代でU方向・V方向にグリッドを張る。目地方向が `staggered` の場合、偶数列(段)を半枚ずらす。
3. **セル判定**:各グリッドセルと面外形(控除領域を差し引いたネット領域)の交差を取り、
   * 完全内包 → **全判**
   * 部分交差 → **切断材**(交差矩形の外接寸法を切断後幅・長さとする。非矩形交差は初期版では外接矩形で切り出し、余りを廃棄面積へ)
   * 交差なし → 配置なし
4. **レコード化**:

```ts
interface PlywoodPlacement {
  panelNo: number;                     // 使用するベニヤ番号(面内連番)
  fullOrCut: "full" | "cut";
  positionUV: Point2D; orientation: 0 | 90;
  cutWidth: number; cutLength: number; // 切断後寸法(全判は規格寸法)
  usedArea: number; wasteArea: number; // 使用面積・余り面積
  memberId: MemberId; faceId: FaceId;  // 対象部材・対象型枠面
}
```

5. **集計**:全判枚数、切断材枚数(1枚の原板から1切断材。端材転用・ネスティングなし=切断材1枚につき原板1枚消費)、合計枚数、使用面積、端材(廃棄見込み)面積、型枠面別内訳。端材一覧(寸法と面積)を表示する(第13章)。
6. **丸め**:`RoundingRule` を最後に適用し、丸め前後を計算書に併記。

## 12. 桟木配置アルゴリズム

入力:型枠面、桟木規格、`BattenPitchConfig`、ベニヤ割付結果(継ぎ目位置)。

1. **基本列**:面のU方向に `PitchRule`(水平ピッチ、左右端オフセット、端部配置有無)で縦桟木のU位置列を生成。
2. **追加配置**:
   * ベニヤ継ぎ目補強:`extraAtPanelJoints=true` のとき、板割り結果の縦目地U座標に追加(既存位置と重複時はスキップ。本数はU-11確定まで1本/箇所を仮置きし「未確定」表示)。
   * 出隅・入隅:`extraAtCorners=true` のとき、面端部の隅種別に応じ追加(本数はU-12未確定 → 未確定表示)。
3. **長さ決定**:各桟木の必要長=面の型枠高さ(V範囲)。高さ範囲別ピッチ指定時は境界で分割し、`continuity` が `separate` なら上下別材、`continuous` なら1本扱い。
4. **材料取り**:必要長ごとに標準長さから切り出し。`spliceAllowed=true` かつ必要長>最長規格なら継ぎ足し(継ぎ位置と本数を記録)。`minUseLength` 未満の切断は不可としてエラー表示。端材は転用しない(切断1本=原材1本消費)。
5. **出力**(第14章):配置本数/使用総延長/規格長さ別必要本数/切断材一覧/端部補強分/ベニヤ継ぎ目補強分 — を**分けて**算出し、各行に計算式を付す。

## 13. 鋼管配置アルゴリズム

入力:型枠面、鋼管規格(形状・本/段・列数・重ね長さ)、鉛直 `PitchRule`(最下段高さ・最上段離れ・二段階対応)。

1. **段位置**:面のV方向に `PitchRule` で水平段のV位置列を生成(`bottomOffset`=最下段の高さ、`topClearance`=最上段からの離れ)。
2. **各段の必要長さ**:当該V位置での面のU方向有効長(控除領域・勝ち負けで欠ける場合は区間分割)。
3. **本数展開**:必要長×`pipesPerRow`(二本抱き=2)×`rowCount`。
4. **材料取り**:標準長さの組合せで各段をカバー。`spliceAllowed=true` なら継ぎ(重ね長さ `lapLength` を加算、`splicePosition=stagger` なら段ごとに継ぎ位置を半ピッチずらす)。継ぎ箇所数を記録。
5. **出力**(第15章):配置段数/各段の必要長さ/使用総延長/規格長さ別本数/継ぎ本数/切断材一覧。丸パイプ・複数列は同じデータ構造でパラメータのみ変更。

## 14. セパレーター配置アルゴリズム

入力:対向する型枠面ペア(`pairFaceId`)、`SeparatorPitchConfig`、セパ規格、Pコン規格、壁厚。

1. **前提チェック**:両面型枠(`double`)の面ペア単位で配置する。片面型枠のセパ扱いは工法依存のため、片面時は「アンカー等別途」として本数0+警告を既定とし、ユーザーが配置有を選んだ場合のみ両面と同様に格子生成する。
2. **格子生成**:`verticalBands` ごとに、鉛直ピッチで段を、各段内で水平 `UniformPitch` により列を生成(帯ごとに水平ピッチ変更可、第19章の例に対応)。左右端・最下段・最上段離れは `edgeOffsets`。
3. **長さ決定**:`SeparatorSpec.lengthRules` から (Pコン種類, 仕上げ条件) に一致するルールを検索し、`長さ = 壁厚 + addend + Pコンの separatorLengthAdjust×2`。**一致ルールなし → 当該面の `calcBlockers` に「セパ長さ未確定」を積み、計算を停止して手入力を要求(推測禁止)**。
4. **規格照合**:算出長が `stockLengths` にあれば規格品、なければ `customLengthRounding` で丸めた特注長として別行計上。
5. **出力**(第16章):配置本数/長さ別本数/構造部材別/型枠面別/Pコン種類別/フォームタイ種類別本数。

## 15. フォームタイおよびPコン数量計算

* **フォームタイ** = Σ(セパ配置本数 × 端部係数)。端部係数は `FormTieSpec` から:両面型枠=`countPerSeparatorEnd×2`(標準:両端各1)、片面型枠=`countPerSideSingle`。対応セパ規格・鋼管形状の整合をチェックし、不整合はエラー表示(自動代替しない)。用途区分(壁用/柱用/梁用)ごとに集計。
* **Pコン** = Σ(セパ配置本数 × `countPerEnd` × 端数[両面=2, 片面=1])。種類別・対応セパ別・部材別に集計。`separatorLengthAdjust` はセパ長さ計算(第14節)に反映済みであることを計算書に明記。
* どちらも丸めは `RoundingRule` を最後に適用し、丸め前の生値を計算書に残す。

## 16. 2D編集画面の仕様

* **レイアウト**:左=ツールパレット、中央=キャンバス、右=プロパティパネル、下=ステップナビゲーション(第23章のステップ3〜6に対応)。
* **背景レイヤ**:読込画像/PDF(不透明度調整、縮尺設定済みなら実寸表示)。縮尺未設定時はキャンバス上部に警告バーを常時表示し、拾い出し実行ボタンを無効化。
* **作図ツール**:ポリライン、長方形、柱(矩形/多角形)、壁(通り+厚さ)、梁(通り+幅)、スラブ(閉領域)、フーチング(矩形)。スナップ:端点/中点/交点/直交/グリッド。
* **編集操作**(第6章):頂点追加(辺上クリック)/削除(Del)/移動(ドラッグ+数値)、辺移動、辺長数値入力(辺クリック→寸法ボックス)、拘束の付与・解除(水平/垂直/平行/直角)、分割(点指定)、結合(端点許容差内)、開閉切替、Undo/Redo(全編集対象、履歴はコマンドパターン)。
* **部材分類**:ポリライン選択→「部材を割り当て」→種類選択→属性入力。同一ポリラインへの追加割り当てで重ね登録(第7章)。部材ごとに色とレイヤ表示切替。
* **取り合い表示**:重複候補をハイライトし、クリックで勝ち負けダイアログ(第9節)。自動控除=黄/手動変更=青/両方計上=赤縞。
* **寸法表示**:選択部材の辺長・厚さ・通り芯寸法を常時表示。すべてmm。

## 17. 3D編集画面の仕様

* **ビュー**:平面/正面/側面/アイソメ/自由回転。透視投影⇔平行投影切替(第8章)。
* **表示ツリー**(材料別オン・オフ、第2章):躯体/ベニヤ/桟木/鋼管/セパレーター/フォームタイ/Pコン。加えて部材別・脱型区分別のフィルタ。
* **高さ編集**:頂点の上下ドラッグ(スナップ:10mm既定、Shiftで自由)、右クリック→数値入力、複数選択して一括変更・コピー、辺の上端勾配指定。初期版は下端の非水平化をUIで禁止(グレーアウト+「将来対応」表示)。
* **確認機能**:配置位置確認(部材クリック→計算書ポップアップ)、干渉確認(材料同士の交差を赤表示)、重複確認(控除領域の色分け)、取り合いクリック→勝ち負け変更(第10章)。
* **手動修正**:個別材料の削除/追加/位置調整。手動修正は `manualAdjustments` として保存され、再計算時に「維持/破棄」を選択できる(第26章)。修正済み数量には「手動補正」マークを付ける(第25章)。

## 18. 数量集計画面の仕様

* **集計軸**(第23章ステップ9):構造部材別/型枠面別/材料別/規格別/長さ別/脱型区分別。ピボット的に軸を切替可能な集計テーブル。
* **脱型区分ビュー**(第11章):先行脱型可能/支保工関連/スラブ底/梁底/最後まで残置 の5区分で材料を分けて表示。梁側と梁底は常に別行。
* **出力項目**(第24章):ベニヤ(規格/向き/全判/切断/合計/使用面積/端材面積/面別内訳)、桟木(規格/本数/総延長/長さ別/切断材/面別)、鋼管(規格/段数/総延長/長さ別/継ぎ箇所/面別)、セパ(規格/長さ/長さ別/合計/部材別)、フォームタイ・Pコン(種類/対応セパ/合計/部材別)。
* **計算根拠ドロワー**(第25章):任意の集計行をクリックすると、入力値→規格→ピッチ→開始/終了位置→本数→計算式→端数処理→重複控除→手動補正→最終数量、の順に表示。控除は junction ID、補正は修正履歴にリンク。
* **不足情報パネル**:`calcBlockers` を持つ面を一覧表示(例「W3 A面:セパ長さルール未登録 → 長さを入力してください」)。不足がある間、当該面の数量は空欄+全体合計に「未計算面あり」の警告。
* **免責注意書き**を画面下部に常時表示。
* **出力**(第23章ステップ10):Excel/CSV/PDF、材料一覧、板割図(面ごとのパネル配置図)、配置図(桟木・鋼管・セパ位置)、3D画像、計算条件一覧(使用マスタとピッチの全パラメータ)。

## 19. 必要なテストケース

### A. 配置計算(単体)

1. 等間隔・固定ピッチ:L=3,640、p=450、offset=0 → 位置列と端部余り140を検証。
2. 等間隔・均等割り:同条件で n=ceil(3640/450)=9 スパン、実ピッチ404.4…の丸め表示。
3. 二段階ピッチ:H=3,000、境界1,500、下450/上600、境界配置あり/なしの両方。
4. 最下段高さ・最上段離れが位置列に正しく効くこと(鋼管・セパ)。
5. startOffset+endOffset > L の異常系:エラーで計算停止(負本数を出さない)。

### B. ベニヤ割付

6. 910×1,820縦使い、壁 W=3,640×H=3,640 → 全判8枚・切断0・端材0。
7. W=4,000×H=3,000 → 全判・切断材の枚数、切断寸法、端材面積の検証。
8. 横使い切替で板割りが90度回転すること。目地 staggered で半枚ずらし。
9. 控除領域(勝ち負け控除)があるセルが切断材/配置なしに正しく分類される。
10. 切断代(kerf)が枚数に影響するケース。

### C. 桟木・鋼管

11. 縦桟木:ベニヤ縦目地への追加配置が既存位置と重複したときスキップされる。
12. 高さ範囲別ピッチ+`separate` で上下別材、`continuous` で1本になる。
13. 鋼管:必要長7,200、規格{4,000, 3,000, 2,000}、重ね300 → 継ぎ本数と総延長。
14. 二本抱き(pipesPerRow=2)で本数が2倍になる。
15. minUseLength 未満の切断要求がエラーになる。

### D. セパ・フォームタイ・Pコン

16. 壁厚180+ルール(addend=+X)+Pコン調整 → 長さ計算と規格/特注判定。
17. **lengthRules 未登録 → 計算停止し不足項目表示(数量が出ないこと)**。
18. 帯別ピッチ(下:450/450、上:600/600)で格子本数を検証。
19. 両面=Pコン2倍・フォームタイ両端、片面=設定値どおり。
20. 対応外の組合せ(セパ規格×フォームタイ)がエラーになる(自動代替しない)。

### E. 勝ち負け・重なり

21. 柱×壁:標準で柱勝ち→壁面に控除領域が入り netArea が減る。
22. ユーザーが B_wins に変更→控除の付け替えと数量移動(quantityOwner)。
23. 両方計上/両方控除/指定長さ控除/指定範囲控除の各policy。
24. 同一ポリラインを壁と梁が参照:高さ・厚さ・材料が独立で、統合されない。
25. 梁側と梁底が別オブジェクト・別脱型区分・別集計行になる。

### F. 入出力・UI

26. 縮尺未設定で拾い出し実行がブロックされる(3方式それぞれの設定で解除)。
27. ポリライン編集のUndo/Redoが拘束・分割・結合を含めて往復できる。
28. 画像トレース結果が `confirmed=false` で生成され、確定操作なしでは部材化できない。
29. 保存→再読込で第26章の全項目が一致(ラウンドトリップ)。
30. 材料条件のみ変更→形状不変で数量だけ再計算。手動補正の維持/破棄が選べる。
31. Excel/CSV/PDF出力の数値が画面集計と一致。免責注意書きが出力に含まれる。
